# Data Encryption Strategy

## Классификация данных

| Данные | Слой | Состояние | Класс | Риск | Необходимость защиты | Защита at rest | Защита in transit |
|---|---|---|---|---|---|---|---|
| ФИО, дата рождения, телефон, email, адрес | Raw / Golden Source | Rest / Transit / Use | PII, Confidential | Высокий | Идентифицируют пациента, возможна утечка персональных данных | AES-256, шифрование дисков/БД, выборочное шифрование полей | TLS 1.3 |
| Диагнозы, анамнез, заключения врача | Raw / Golden Source | Rest / Transit / Use | Medical, Restricted | Критический | Наиболее чувствительные медицинские данные | AES-256, шифрование БД и резервных копий, KMS | TLS 1.3, mTLS между сервисами |
| Результаты лабораторных исследований | Raw / Processed | Rest / Transit / Use | Medical, Restricted | Критический | Медицинская тайна, передаются внешней системой | AES-256 | mTLS между Медикаменте и лабораторией |
| Запись к врачу | Golden Source | Rest / Transit | PII, Confidential | Высокий | Связывает пациента, врача, время и медицинский контекст | Шифрование БД | TLS |
| Медицинские JPG/PDF/Excel | Raw | Rest / Transit | PII + Medical, Restricted | Критический | Содержат неструктурированные PII и медицинские сведения | Шифрование файлового/object storage, encrypted backup | TLS/SFTP вместо незашифрованной передачи |
| Платежи и суммы | Golden Source | Rest / Transit | Financial, Restricted | Высокий | Финансовая информация и связь платежа с пациентом | AES-256, шифрование БД/диска | TLS |
| Кадровые данные сотрудников | Golden Source | Rest / Transit | HR + PII, Restricted | Высокий | Персональная и кадровая информация сотрудников | Шифрование хранилища и backup | TLS |
| Зарплата и налоговые данные | Golden Source | Rest / Transit | HR + Financial, Restricted | Высокий | Конфиденциальная финансовая информация | AES-256 | TLS |
| Данные для BI | Processed | Rest / Transit / Use | Internal / Confidential | Средний | Для аналитики не требуются прямые идентификаторы | Шифрование Data Lake/DWH | TLS |
| Данные для ML/AI | Processed | Rest / Transit / Use | Internal / Confidential | Средний/Высокий | Возможна повторная идентификация пациента | Шифрование + псевдонимизация/анонимизация | TLS |
| Audit logs | Processed | Rest / Transit | Confidential | Высокий | Содержат пользователей, действия и иногда идентификаторы объектов | Шифрование хранилища логов, ограничение доступа | TLS |
| Секреты, пароли, API keys | Golden Source | Rest / Transit / Use | Secret | Критический | Компрометация даёт доступ к системе | Vault/KMS, не хранить в коде или конфигурации открытым текстом | TLS/mTLS |


## Стратегия защиты

Для данных класса Restricted и Secret применяется максимальный уровень защиты.

Основные принципы:

- данные at rest шифруются с использованием AES-256;
- диски серверов и резервные копии должны быть зашифрованы;
- наиболее чувствительные поля могут дополнительно шифроваться на уровне приложения;
- ключи шифрования не хранятся вместе с данными;
- ключи централизованно хранятся и ротируются через KMS/Vault;
- весь внешний и внутренний сетевой трафик с конфиденциальными данными передаётся по TLS;
- для service-to-service и интеграции с лабораторией используется mTLS;
- для аналитики данные минимизируются и псевдонимизируются;
- секреты и API keys запрещено хранить в Git и открытых конфигурационных файлах.


## Data Encryption at Rest

### Базы данных

- шифрование файловой системы или диска;
- AES-256;
- чувствительные поля могут дополнительно шифроваться на уровне приложения;
- резервные копии также должны быть зашифрованы.

### Файлы и Data Lake

- server-side encryption / AES-256;
- разграничение доступа;
- отдельные ключи для различных категорий данных.

Полное шифрование дисков на ноутбуках и серверах;

Ключи хранятся отдельно от данных в KMS/Vault.

## Data Encryption in Transit

Использовать TLS 1.3 для всех соединений, включая:

mTLS позволяет одновременно шифровать соединение и проверять
подлинность обеих сторон.

Для новых интеграций запрещается передача PII и медицинских данных
по незашифрованным HTTP, FTP или другим открытым протоколам.


## Data in Use

Для данных, которые обрабатываются приложениями:

- применять Data Minimization;
- не загружать лишние данные в память;
- маскировать PII в интерфейсах и логах;
- не записывать токены, пароли, медицинские данные и полные PII в application logs;
- использовать псевдонимизированные данные для BI/ML;
- ограничивать доступ через RBAC/ABAC.


## Автоматизированный контроль

| Контроль | Назначение |
|---|---|
| Data Catalog / OpenMetadata | Автоматическая классификация и тегирование PII/MEDICAL/FINANCIAL |
| Vault / KMS | Управление и ротация ключей |
| cert-manager / PKI | Выпуск и автоматическая ротация TLS-сертификатов |
| Gitleaks | Поиск API keys, паролей и секретов в Git |
| pgAudit | Аудит обращений к данным PostgreSQL |
| SIEM / Elastic | Анализ audit/security logs и формирование алертов |
| DLP | Поиск и блокировка несанкционированной передачи конфиденциальных данных |
| OPA / Conftest | Автоматическая проверка security-политик конфигурации в CI/CD |


Контроль должен автоматически выявлять:

- использование HTTP вместо HTTPS;
- просроченные TLS-сертификаты;
- секреты и API keys в Git;
- незашифрованные хранилища;
- незашифрованные резервные копии;
- передачу Restricted-данных в системы, которые не должны их получать;
- появление PII/MEDICAL в логах;
- массовое или нетипичное чтение медицинских данных;
- нарушение RBAC/ABAC;
- отсутствие обязательных тегов PII/MEDICAL/FINANCIAL.

## Политики защиты по классу данных

| Класс | At Rest | In Transit | Дополнительно |
|---|---|---|---|
| Public | Не обязательно | TLS | — |
| Internal | Шифрование storage | TLS | RBAC |
| Confidential | AES-256 | TLS | RBAC/ABAC, Audit |
| Restricted | AES-256 + field encryption при необходимости | TLS/mTLS | Audit, KMS, masking, DLP |
| Secret | Vault/KMS | TLS/mTLS | Rotation, запрет хранения в Git |
