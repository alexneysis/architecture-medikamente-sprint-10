# Данные, требующие защиты

| Категория | Примеры | Защита                                     |
|---|---|--------------------------------------------|
| PII пациента | ФИО, дата рождения, телефон, email, адрес | Шифрование, маскирование, контроль доступа |
| Медицинские данные | диагнозы, заболевания, заключения | Шифрование, строгий RBAC/ABAC, аудит       |
| Анализы | результаты исследований | Шифрование, маскирование для аналитики     |
| Записи к врачу | пациент, специалист, дата и время | Шифрование, контроль доступа               |
| Финансовые данные | платежи, услуги, суммы | Шифрование, маскирование                   |
| PII сотрудников | ФИО, кадровая информация | Шифрование, контроль доступа               |
| Зарплата | выплаты и налоговые данные | Шифрование, ограниченный доступ            |
| BI/ML datasets | агрегированные данные пациентов | Шифрование, маскирование                   |
| JPG/PDF/Excel | медицинские документы и анкеты | Шифрование, тегирование                    |


# Тегирование данных

Для централизованной классификации данных предлагается использовать
OpenMetadata.

Для каждого объекта данных назначаются теги.

## Уровень конфиденциальности

PUBLIC
INTERNAL
CONFIDENTIAL
RESTRICTED

## Категория

PII
MEDICAL
FINANCIAL
HR

## Владелец данных

PATIENT
EMPLOYEE

Примеры:

ФИО пациента:
CONFIDENTIAL + PII + PATIENT

Телефон:
CONFIDENTIAL + PII + PATIENT

Диагноз:
RESTRICTED + MEDICAL + PATIENT

Результат анализа:
RESTRICTED + MEDICAL + PATIENT

Зарплата:
RESTRICTED + FINANCIAL + HR

1. Источник данных регистрируется в каталоге.
2. Поля и наборы данных получают теги.
3. Для тегов задаются политики доступа.
4. При передаче данных тег сохраняется.
5. Data Lineage фиксирует движение данных между системами.
6. Для аналитики данные с тегами PII/MEDICAL обезличиваются.
7. Доступ к данным RESTRICTED записывается в журнал аудита.


# Средства защиты

## Контроль доступа

Использовать RBAC/ABAC.

Примеры:

Reception:
- PII пациента — чтение/изменение
- запись к врачу — чтение/изменение
- медицинская карта — нет доступа

Doctor:
- PII своего пациента — чтение
- медицинская карта — чтение/изменение
- финансовые данные — нет доступа

Cashier:
- данные, необходимые для оплаты — чтение
- медицинские данные — нет доступа

Bookkeeper:
- финансовые данные — чтение/изменение
- медицинские данные — нет доступа

Patient:
- только собственные данные.

## Технические меры

- TLS не ниже 1.3 для передачи данных.
- mTLS для интеграции с лабораторией.
- Шифрование данных at rest AES-256.
- Централизованное управление ключами.
- RBAC/ABAC.
- Маскирование PII.
- Обезличивание данных для BI/ML.
- Data Catalog и tagging.
- Data Lineage.
- Аудит доступа.
- Централизованный сбор логов.
- DLP для предотвращения утечек.
- Шифрование резервных копий AES-256.
- Политики retention и удаления данных.
