## Классы конфиденциальности

| Класс | Пример | Действие |
|---|---|---|
| PUBLIC | публичные справочники | загрузка без дополнительных преобразований |
| INTERNAL | внутренние технические данные | контроль доступа |
| CONFIDENTIAL | ФИО, телефон, email | masking / pseudonymization |
| RESTRICTED | диагнозы, анализы, медицинские документы | строгий доступ, encryption, anonymization |


## Слои хранения данных

### Secure Raw Layer

Хранит исходные данные после загрузки.

Особенности:

- минимальный круг пользователей;
- encryption at rest;
- обязательный аудит;
- данные могут содержать PII и MEDICAL;
- доступ BI/ML напрямую запрещён.

### Classified / Curated Layer

Данные очищены и классифицированы.

Для каждого поля определены:

- класс конфиденциальности;
- тип данных;
- владелец;
- правила доступа;
- правила masking.

### Anonymized Analytics Layer

Используется BI, ML и AI.

Перед загрузкой:

- удаляются лишние поля;
- прямые идентификаторы маскируются;
- данные псевдонимизируются или анонимизируются.

BI и ML должны преимущественно работать именно с этим слоем.


## Метрики эффективности классификации

| Метрика | Назначение |
|---|---|
| Precision | Сколько найденных конфиденциальных данных действительно являются конфиденциальными |
| Recall | Сколько реальных конфиденциальных данных удалось обнаружить |
| F1-score | Общая оценка качества классификации |
| Classification Coverage | Доля полей, которым удалось назначить класс |
| Unknown Fields Rate | Доля полей, которые движок не смог классифицировать |
| False Negative Rate | Сколько конфиденциальных данных ошибочно признаны безопасными |
| Processing Time | Время обработки одного batch |
| Throughput | Объём данных, классифицируемый за единицу времени |
| Schema Drift Count | Количество обнаруженных изменений схем |


## Scalability

Classification Engine проектируется как stateless-компонент.

Для масштабирования:

- batch разбивается на независимые partitions;
- задачи обработки передаются через очередь;
- Classification Workers масштабируются горизонтально;
- число workers увеличивается при росте backlog;
- данные хранятся в масштабируемом object storage;
- metadata и схемы хранятся отдельно в Schema Registry / Data Catalog.

При увеличении объёма данных:

1. увеличивается количество workers;
2. batch делится на большее число partitions;
3. увеличивается вычислительная мощность ETL-платформы.
